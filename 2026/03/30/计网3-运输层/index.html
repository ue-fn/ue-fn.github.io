运输层1

运输层基础

运输层提供应用进程之间的逻辑通信

运输协议运行在端系统，路由器不处理运输层头部

  • 发送方：把应用消息切分成报文段，交给网络层
  • 接收方：把报文重组为完整消息，交给应用层
  • 最核心的两个运输协议：TCP , UDP

为什么需要运输层？

  • IP 把数据包送到主机，但主机上跑很多应用，必须区分给哪个进程。
    • 发送端多路复用（Multiplexing）：运输层把这些不同应用的数据收集、打包、加上头部，一起交给网络层
    • 接收端多路分用(demultiplexing)：运输层查看接收数据包头部信息，判断这个数据属于哪个应用。把数据递交给对应的正确的进程（socket）
  • 数据包可能：损坏、丢失、延迟、乱序、重复。
    • 给应用层提供通用服务，避免每个应用自己实现可靠传输，运输层统一解决。
    • 让应用开发变得简单

Role of the transport layer

  • 应用进程之间的通信
  • 为应用层提供通用的、端到端的服务（可选不同的协议）
    • 可靠、按序的数据交付
    • 节奏合适的数据发送（快了拥堵）
  • TCP和UDP（等等）
  • UDP：极简主义的运输协议，只提供多路复用和多路分用（分段，可能乱序）（不握手，域名直接发）
  • TCP：offers a reliable, in-order, byte stream abstraction（字节流服务，没有天然分段）（会握手）

应用与套接字

  • sockets：套接字：软件抽象,通信接口，让应用进程能够和操作系统内部的传输层，互相交换网络消息
    • 传输层地址<HostIP, Port>定位主机，定位进程
    • 两种重要的socket类型：
      • UDP Socket：SOCK_DGRAM：只记录本地ip，本地端口
      • TCP Socket：SOCK_STREAM：本地ip，本地端口，远程ip，远程端口

端口：

  • 16位数字，区别不同程序

    • 数据包在传输层头部里，必须携带源端口和目的端口

    • 分两类，知名端口（0-1023）给系统固定服务用，临时端口给客户端程序随便用

  • 操作系统存储套接字和端口之间的映射关系

复用&分用

  • 发送方：复用。把多个 socket 发来的数据收集起来，给每一段数据加上传输层头部，交给网络层发走
  • 接收方：分用：
    • 收到网络发来的ip数据段，
    • 看传输层头部里的端口信息，ip包里有源ip，目的ip和传输层报文段
    • 根据这些信息，把数据交给正确的 socket，再交给对应的应用进程

​ udp分用：主机接收到UDP包，只看目的端口，只要目的端口一样，不管谁发来的，都进同一个 UDP socket

​ TCP分用：四元组，一条连接一个 socket

为什么需要运输层？

IP provides a weak service model (best-effort)：

可能会出现各种问题

没有发送规则（how much & when）

让每个写软件的人，自己处理丢包、错包、乱序、流量控制，太累

解决这些问题的机制

Checksums：检测错误

ACKs：告诉发送方收到了

NACK：告诉发送方没收到 / 出错了

  • 如果这两个也出错？让他们带序号
  • 处理丢失：发送方发出时启动计时器，规定时间内没收到就判定丢包，立即重传
  • 超时重传会有重复包，靠序号去重

Sequence numbers：给包编号

Retransmissions：重发

Timeouts：超时就重发

Forward error correction：前向纠错

Network encoding：网络编码

Designing a reliable transport protocol

stop and wait：可靠但是低效

Pipelined protocols（流水线协议）不等 ACK，连续发多个包

  • 发送方能发哪些包？——滑动窗口控制
    • 一次最多发 n 个包，不用一个个等 ACK
    • 每成功收到并确认一个包，窗口就右滑
  • 接收方怎么确认收到？——累计确认/选择性确认
  • 丢包时发送方重传哪些包？——Go-Back-N (GBN)/Selective Repeat (SR)

只要窗口足够大，滑动窗口协议能跑满链路带宽

发送方必须缓存所有还没被确认的包

接收方可以收乱序包，但有缓存上限

实现复杂度：GBN 简单，SR 复杂
