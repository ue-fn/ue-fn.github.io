计网5-链路层和局域网

  • 2026-06-12
  • 作者 ue-fn
  • ~6.96K 字

introdution

链路层负责“相邻节点之间”的传输

  • node节点：主机、路由器都叫节点

  • 连接相邻节点的通信通道，可以是有线，无线，局域网

  • frame帧：链路层的数据包，里面封装了网络层的 datagram

  • 同一个 IP 数据报，在每一跳都会被重新封装成当前链路适合的帧

    • （比如wifi，以太网（物理线））

  • 每个连接协议提供不同服务

链路层服务

  • 成帧：把datagram封装成帧，加入链路层头部和尾部
  • 链路接入：如果是共享传输介质
  • MAC地址：链路层帧头部有MAC地址，和ip地址不同

链路层可做可靠运输：但是以太网这种有线链路误码率低，通常不在链路层大费周章重传。
无线链路误码率高，比如 WiFi、蜂窝网络

  • 还有流量控制，
  • 差错检测，
  • 差错纠正
  • 半双工 / 全双工：半双工两端都能发，不能同时发。全双工两边可以同时发。

链路层的实现：

  • 通常实现在 network interface card，NIC，网卡 中，也可能集成在芯片里。

  • 网卡不只负责链路层，也负责一部分物理层功能。

  • 网卡接入主机总线

  • 链路层由硬件，软件和固件三者协同实现

链路层通信：

  • 发送端：封装，加上错误检测位，流控信息
  • 接收端，检查错误，取出datagram

Error detection, correction

奇偶校验：

加一个校验位，让整个bit串里的1有偶数个

二维奇偶校验

数据排成矩阵，然后每行每列奇偶校验

可定位可误判

互联网校验和

UDP segment 的内容看成一串 16-bit 整数，然后反码加法，得到checksum

CRC：循环冗余校验

把数据 bit 串当成一个二进制数，用一个约定好的生成器 G 去除它。发送方故意补上一段 R，使得最终发送的 bit 串能够被 G 整除。接收方再除一次，如果除不尽，就说明出错了

D = data bits，原始数据
G = generator，生成多项式/生成比特串
R = CRC bits，要补上的校验位

发送方发送DR

在MOD2里，加法减法都是XOR

获得R：在D后面补上r个0.除完余数放在D后面发送

Multiple access protocols

当很多节点共用同一条链路/同一个无线信道时，谁可以在什么时候发送？

两种链路：

点对点

广播，共用同一个传输媒介

两个或更多节点同时发送，就会产生 interference；如果一个节点同时收到两个或更多信号，就叫 collision。Multiple access protocol 是一个分布式算法，用来决定节点如何共享信道，也就是每个节点什么时候可以发送。

理想的multiple access protocol ……

MAC 协议三大类

  1. channel partitioning：信道划分
  2. random access：随机访问
  3. taking turns：轮流访问

信道划分协议

TDMA：按时间分。

时间被切成一轮一轮的 slot，每个节点在每一轮里分到固定的时间槽。

FDMA：按频率分

把总频谱分成多个频带，每个节点固定使用一个频带

这两个，高负载时公平稳定，低负载时浪费资源。

随机接入协议

不提前固定分配信道。节点有数据就尝试发送；如果撞了，再想办法恢复

  1. how to detect collisions：怎么发现碰撞
  2. how to recover from collisions：碰撞后怎么恢复

e.g.Slotted ALOHA

假设：

所有 frame 大小相同
时间被分成等长 slot
每个 frame 正好用一个 slot 传完
节点只能在 slot 开头发送
所有节点 slot 同步
如果两个或更多节点同一 slot 发送，则发生 collision

操作：

节点有新 frame，就在下一个 slot 发送
如果成功，下一个 frame 继续发
如果碰撞，则之后每个 slot 以概率 p 重传，直到成功

效率：不高

e.g. CSMA (carrier sense multiple access)

如果信道空闲：发送整个 frame
如果信道忙：先等，等空闲后再发

但是因为传播延迟，同样会有碰撞

e.g. CSMA/CD:

发送前先听，发送时还继续检测有没有碰撞

在有线以太网里，边发边听比较容易；但在无线里很难

Ethernet CSMA/CD 算法

  1. 网络层交给以太网一个 datagram，以太网封装成 frame
  2. 侦听信道
    • 如果 idle，开始发送
    • 如果 busy，等到 idle 再发送
  3. 如果整个 frame 发完都没碰撞，成功
  4. 如果发送过程中检测到别人的传输，说明碰撞：
    • abort，停止发送
    • send jam signal，发送干扰信号，让其他节点也知道碰撞发生
  5. 进入 binary exponential backoff，二进制指数退避

然后等待：

再回去重新侦听、尝试发送。

碰撞次数越多，等待范围越大

轮流协议

想要结合前两类的优点

  1. polling轮询

有一个 centralized controller，中心控制器，轮流邀请各个节点发送。（蓝牙就是）

  1. Token passing

网络里传递一个特殊控制消息 token，谁拿到 token，谁才能发送

一个节点故障导致整个信道崩溃

Cable access network：FDM、TDM、随机访问混合使用

下行方向，也就是 CMTS 到用户 cable modem：
广播，一个中心往下发。PPT 说 Internet frames、TV channels、control 会在不同下行频率上传输，也就是用 FDM

上行方向，也就是多个用户 cable modem 到 CMTS

上行：TDM

某些 slot 由 MAP frame 分配
某些 slot 用于随机竞争请求
竞争失败后用 binary backoff

LANs

它们负责的范围不同。

地址 属于哪层 作用范围 作用
IP 地址 网络层 跨网络、跨子网 决定最终目的地、路由
MAC 地址 链路层 当前局域网/当前这一跳 把 frame 交给同一链路上的某个接口

IP 地址是 32-bit 的网络层地址，用于三层转发；MAC 地址通常是 48-bit，用于在本地把 frame 从一个接口送到另一个物理连接的接口

并不是主机或者路由器有链路层地址，而是它们的适配器（网络接口）有MAC地址。

MAC地址被设计为永久的，全局唯一。

IP地址仅在本网段唯一

MAC 地址：相对固定，跟接口绑定
IP 地址：跟当前所在网络/子网有关

MAC 地址是扁平地址，可以随着接口移动；IP 地址有网络层次结构，取决于你接入哪个子网。

ARP地址解析协议

知道对方 IP，怎么知道对方 MAC？

ARP表：每个主机或路由器在 LAN 上都会维护一个 ARP table

IP 地址 → MAC 地址 → TTL

TTL 是缓存有效时间

e.g.A 想给 B 发数据，A 已经知道 B 的 IP 地址，但 A 的 ARP 表里没有 B 的 MAC 地址。

  1. A 广播 ARP query，目的 MAC 地址是广播地址：FF-FF-FF-FF-FF-FF
  2. B 给 A 发 ARP response，给出自己的 MAC address
  3. A 收到 B 的回复后，把映射写入自己的 ARP table

如果A和b都在一个子网里：IP 目的地和 MAC 目的地都是 B

如果子网不同，MAC的目的地址不是B：
A 要经过路由器 R，把 datagram 发给另一个子网里的 B

设定 A 知道 B 的 IP，知道第一跳路由器 R 的 IP，也知道 R 的 MAC 地址

  1. 跨子网发送时，IP 地址不变，MAC 地址逐跳变

    A 构造 IP datagram：

    IP src = A 的 IP
    IP dest = B 的 IP

    第一跳以太网帧是 A 发给 R，所以 frame 里是

    MAC src = A 的 MAC
    MAC dest = R 在 A 所在 LAN 上的 MAC

  2. R 收到这个 frame，把链路层外壳拆掉，取出里面的 IP datagram。R 查路由表，发现要从另一个接口转发给 B

Ethernet

有线网的主流技术

物理拓扑：

bus总线已落伍

switched：中间有一个二层交换机，每台主机都有一条单独链路连到交换机

以太网帧结构：

  1. 前同步码（8）：用于同步发送方和接收方的时钟频率

​ 7 bytes of 10101010
​ followed by 1 byte of 10101011

​ 唤醒接收适配器，同步时钟频率

  1. 源地址/目标mac地址

    网卡收到除了自己或者广播的就丢弃

  2. type上层协议类型：IPV4 / IPV6 / ARP / 其它。用于接收器解复用

  3. 数据字段

  4. CRC（4）循环冗余校验

以太网提供无连接，不可靠服务

不握手，不ACK/NAK

802.3 Ethernet standards：同一套 MAC，不同物理层

Ethernet 标准很多

链路层 MAC/frame 格式相对统一
物理层可以换不同线缆、不同速率、不同编码方式

交换机

接收 Ethernet frame
查看 frame 的 MAC 地址
决定要不要转发、转发到哪个端口

  • store-and-forward：把 frame 收进来，再转发出去
  • transparent：主机通常不知道交换机的存在
  • plug-and-play：插上就能用。
  • self-learning：交换机会自己学习 MAC 地址在哪个端口
    • 转发表：(MAC address, interface, timestamp)
    • 不知道目的在哪就广播，如果端口收到不对的就丢

交换机可以同时传多路。不同输入输出端口之间可以并行；同一个输出端口会形成竞争，需要缓存排队。

但是

校园网不是一台交换机：真实 LAN/校园网络是分层的。

Switches vs routers：交换机和路由器区别

  • 交换机

    • link-layer device
      看链路层头部
      看 MAC 地址
      转发 frame
      转发表通过 self-learning/flooding 学出来

  • 路由器

    • network-layer device
      看网络层头部
      看 IP 地址
      转发 datagram
      转发表通过 routing algorithms / routing protocols 计算出来

VLANs

如果一个组织的所有设备都在一个巨大的二层LAN里，

  • 广播流量会穿过整个LAN。
  • 管理用户：移动主机必须改变物理布线

按端口划分VLAN：

支持VLAN的交换机允许经一个单一的物理局域网设施定义多个虚拟局域网。

  • 流量隔离
    • EE 的广播不会跑到 CS
      CS 的广播不会跑到 EE
  • 动态成员关系
  • VLANs之间通信靠路由（路由器/三层交换机）要通过三层网关

VLAN干线连接（trunking）跨交换机VLAN

VLAN 不一定只在一台交换机内部，两台交换机之间要连接起来

但交换机之间传 frame 时，怎么知道这个 frame 属于哪个 VLAN？

trunk port 是交换机之间的特殊端口，用来承载多个 VLAN 的 frame

802.1Q VLAN frame format

让跨交换机传输的 frame 带上 VLAN 身份

VPN / VXLAN：把二层网络“拉长”

Link virtualization: MPLS

目标：为了高速ip转发，使用固定长度label（代替最匹配的ip前缀）加快查表

2.5层

  • MPLS capable router 又叫 label-switched router，

  • 它根据 label value 转发 packet，不检查 IP address，并且 MPLS forwarding table 和 IP forwarding table 是不同的。

  • 灵活：可以基于source address，目的地址决定不同的路径

  • fast reroute：如果某条链路坏了，MPLS可以提前准备备用路径

MPLS signaling：标签路径

  • 修改 OSPF / IS-IS，让它们携带更多链路信息，比如链路带宽，已预留带宽
  • RSVP-TE：入口 MPLS 路由器会沿着选好的路径发信令，让路径上的每个 MPLS 路由器安装标签转发表项

没有 MPLS：
每个路由器看目的 IP 转发

有 MPLS：
进入 MPLS 域时看 IP 决定标签
域内主要看 label 转发
离开 MPLS 域后继续按 IP 转发

Data center networking

A day in the life of a web request

一台刚接入网络的笔记本，怎样一步步访问 www.google.com 并显示网页？

  1. 刚连上网，还没有ip

    connecting laptop 需要获得自己的 IP 地址、first-hop router 地址、DNS server 地址，所以要使用 DHCP。DHCP 报文会被封装进 UDP，再封装进 IP，再封装进 802.3 Ethernet frame。因为客户端一开始还不知道具体服务器在哪，所以以太网帧用广播目的地址 FF:FF:FF:FF:FF:FF 发到 LAN 上，由运行 DHCP server 的路由器收到。

​

  1. DHCP 服务器回复：你可以用这个 IP

    DHCP server 收到请求后，会给客户端一个回复。回复包含

    客户端自己的 IP 地址
    客户端第一跳路由器的 IP 地址
    DNS server 的名字和 IP 地址

    然后这个 DHCP ACK 被封装后经过 LAN 里的交换机转发回来，客户端逐层解封装，最终 DHCP client 收到 ACK。此时客户端终于知道：我的 IP 是多少、默认网关是谁、DNS 服务器是谁。

    电脑获得：client IP address
    first-hop router IP address
    DNS server IP address

  2. 要访问网站，先得知道网站 IP

    客户端要向 DNS server 问：www.google.com 的 IP 地址是多少？

    DNS query 已经创建并封装进 UDP/IP/Ethernet；为了把 frame 发给 router，需要 router interface 的 MAC 地址，于是客户端广播 ARP query，路由器收到后用 ARP reply 回复自己的 MAC 地址。之后客户端才知道第一跳路由器的 MAC，从而可以发送包含 DNS query 的 frame。

  3. DNS 查询被路由到 DNS server

  4. 包含 DNS query 的 IP datagram 会先通过 LAN switch 从客户端转发到 first-hop router，然后从校园网进入 Comcast network，再根据由 RIP、OSPF、IS-IS、BGP 等路由协议建立的路由表，被路由到 DNS server。DNS server 解封装到 DNS 层后，回复 www.google.com 的 IP 地址

  5. DNS 回复回来：客户端知道 Google 服务器 IP

  6. 建立 TCP 连接

    client first opens TCP socket to web server，然后 TCP SYN segment 作为三次握手第一步，被跨域路由到 Web server；Web server 回复 TCP SYNACK，之后 TCP connection established。

  7. 发送 HTTP request

    HTTP request 被送入 TCP socket，包含 HTTP request 的 IP datagram 被路由到 www.google.com，Web server 返回包含网页的 HTTP reply，最后网页才显示出来

  8. Web server 回复 HTTP response：

    HTTP/1.1 200 OK
    Content-Type: text/html
    …
    网页内容
